# CMS Cookie Co. & More

Website for Shaun Marie Schwartz's home bakery in South Lyon, MI: **cmscookieco3more.com**.

It runs as a Cloudflare Worker with static assets, D1 for data, R2 for photos and videos, and Email Routing for order notifications. Shaun manages specials, events, media, menu prices and orders at `/admin`, which Cloudflare Access protects.

## Layout

```
public/                  static site (served by the Worker's assets binding)
  index.html             home page, the flyer design (formerly Concept 2)
  admin/index.html       phone-first admin app
  admin/studio.js        Photo Studio (frame / brighten / words / stickers), canvas only
  admin/help/            "Show me" pictures + clips, generated by `npm run guide`
  kitchen/               public page for adding the CMS Admin icon to a home screen
  concepts/modern/       Concept 1, kept for reference (unlinked, noindex)
  assets/                logo, flavor photos, flyer images
src/worker.js            routes: /api/content, /api/orders, /media/*, /admin, /api/admin/*
src/access.js            Cloudflare Access JWT verification
migrations/              D1 schema + seeded menu
seed/, scripts/          local-only demo content and the guide runner (never run against production)
guide/tasks.json         the Help guide: every task's words and the taps that make its pictures
test/                    node --test suite (Access, orders, media, Photo Studio, flavors/treats, guide)
DEPLOY.md                one-time production setup, step by step
```

## Run it locally

```sh
cd site
npm install
cp .dev.vars.example .dev.vars   # lets /admin work on localhost without Access
npm run seed:dev                 # local D1 migrations + demo specials/events/media + local R2 files
npm run dev                      # http://localhost:8787  and  http://localhost:8787/admin/
npm test
npm run guide                    # re-make the admin Help pictures + clips (needs ffmpeg; see below)
```

Local D1 and R2 data live in `.wrangler/state` (gitignored). Order emails don't send locally. Wrangler logs each one and saves a copy under `.wrangler/tmp/email`.

## Help guide ("Show me")

`guide/tasks.json` holds each Help task: its title, the caption for every step, and the control each step taps. `npm run guide` re-seeds **local** data, replays every task in a 390×844 phone-sized Chromium against `wrangler dev` (it starts one if needed), and writes `public/admin/help/<task>/N.webp` (the tapped control circled in pink), `clip.mp4` (silent H.264, 20 s or less, under 1.5 MB) and `guide.json`, which the admin Help tab reads. Change the words or the steps in `tasks.json`, never in the output. Run it after any admin UI change, then `npm test` (it fails if the Help words and `tasks.json` disagree). One-time setup: `npx playwright install chromium` and ffmpeg on PATH. `npm run guide photo cotm` re-makes just those tasks.

## How things work

- **Flavors** are `menu` rows with `kind = 'flavor'` (short name, description, photo, optional start/end dates, in-flight flag); **treats** are rows in `treats`. Shaun adds, reorders and switches them off in Admin → Menu. Anything off or outside its dates is hidden and refused at checkout.
- **Photos** picked in admin go through the Photo Studio, which uploads a framed WebP (≤ 1600 px, ≤ 400 KB) plus the untouched original (≤ 2400 px) so "Edit photo" can start over. The shape follows where the photo goes, and the home page shows that same shape: circle (Cookie of the Month, flavors), square (treats, gallery), 4:3 (specials), whole (event flyers, tap to enlarge).
- **Prices** live in the D1 `menu` table. The page shows the flyer prices first, then updates them from `/api/content`. Checkout sends only item types and quantities, and the Worker re-prices every order from D1, so a tampered browser can't change a total.
- **Orders** are validated, stored in D1, and emailed to Shaun from orders@cmscookieco3more.com. If the API is unreachable, the checkout's text, email and copy buttons still work.
- **Payments** (`payment_methods`): Shaun switches Venmo, Cash App and cash at pickup on/off and sets the names in Admin → Payments. Checkout and the contact panel show only what's on; the Venmo QR is drawn from the stored name by `public/assets/qr.js` (no CDN). Card (Square) is a greyed "coming soon" row until the Worker has Square secrets (DEPLOY.md §8). Then Shaun taps **Connect Square** (OAuth; tokens AES-GCM encrypted in D1), switches Card on, and customers get **Pay with card**: the server saves the order, makes a Square-hosted payment link for its own total, and marks the order **Paid by card** from Square's signed webhook or by asking Square when the customer comes back. Card details never touch the site. Admin can also **Send pay link** for any unpaid order, signup or quoted request. `src/square.js` has it all.
- **Cookie of the Month and Specials** are rows in `specials` (`kind` = `cotm` or `special`). They show while `active` is on and today falls within their `starts`/`ends` dates.
- **Events** show until their date passes, and only when Published (a Draft shows only in admin). An event can take signups on the site (`registrations`): price per spot, optional number of spots and closing date. The Worker prices the spots and checks the spots left inside the same INSERT, so the last spot can't be sold twice. Signups share the orders' per-device limit and email Shaun. Admin → Events → Signups shows who's coming (Paid / Checked in) and a "Preview" opens `/?preview=<id>` for a signed-in admin, posting to `/api/admin/events/<id>/register`.
- **Spreadsheets:** `/api/admin/orders.csv?from=&to=` and `/api/admin/events/<id>/registrations.csv` (UTF-8 with BOM, readable dates, dollars). They sit under `/api/admin`, so Access and `ADMIN_EMAILS` protect them. Cells that start like a formula get a leading `'`.
- **Tip of the Week** is the newest featured video or Instagram link in `media`. Featured photos show in a strip under it.
- **Admin security:** Cloudflare Access sits in front of `/admin` and `/api/admin/*`, and the Worker separately verifies the Access JWT on every request (signature, audience, issuer, expiry). Admin writes must also be same-origin.

## Edit contact info

Venmo and Cash App names are in Admin → Payments. Phone and email are in the `CONFIG` block near the top of the `<script>` in `public/index.html`. The notification addresses are in `wrangler.jsonc` (`NOTIFY_TO`, `NOTIFY_FROM`, and the `send_email` allowlist).
